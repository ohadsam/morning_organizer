# Architecture

```
            ┌──────────────────────────── web/ (single source of UI, no build, no runtime deps) ───────────────────────────┐
 GitHub     │  index.html + CSP('self')   sw.js (offline)   manifest                                                        │
 Pages ───► │  js/app.js  router ─► ui/{home,editor,runner,stats,settings,share,guide}.js   (DOM via h(), text nodes only)  │
            │         │                      │                                                                              │
            │         ▼                      ▼                                                                              │
            │  store.js (state, normalize, backup)  ◄── engine.js (run state machine, pure, `now` injected)                 │
            │     │   │                                  stats.js (series, insights, pure)    share.js (encode/decode/sanitize)│
            │     ▼   ▼                                  alarms.js (next fire, pure)           i18n.js (he/en, RTL)           │
            │  db.js (IndexedDB + memory fallback)       audio.js (beep/vibrate)  reminders.js (web-only alarms)             │
            │                         native.js ── no-op in browsers ──────────────────────────┐                               │
            └─────────────────────────────────────────────────────────────────────────────────┼───────────────────────────────┘
                                                                                              ▼  window.MorningNative
 APK (GitHub Releases, always latest)   android/  MainActivity (WebView on https://appassets.androidplatform.net, assets = ../web)
                                         NativeBridge ─► AlarmStore/AlarmMath ─► AlarmManager.setAlarmClock ─► AlarmReceiver ─► AlarmService (sound+vibration)
                                                      ─► RoutineWidget (RemoteViews, favourites)    BootReceiver (re-arm)    NFC read/write + share sheet
```

* **Coach & voice.** `feedback.js` (encouragement + gender/age personalisation, pure) and `coach.js`/`coachTips.js` (35 tips × 3 audience tiers × 2 languages, trigger rules, pure) feed `ui/runner.js`/`ui/coach.js`; `speech.js` wraps the device TTS (styles = pitch/rate presets).
* **Manual sync (website ↔ app).** The two keep separate IndexedDB stores; `share.js` packs a whole backup into a sync code (`MB1.`), `store.importBackup` merges (newest `updatedAt` wins, history unioned by id, settings whitelisted) or replaces. In the APK, `NativeBridge.saveFile` + `MainActivity` (CreateDocument / OpenDocument file chooser) do what the WebView cannot.
* **Family linking.** `link.js` (pure + WebCrypto: AES-GCM envelopes `ML1.<linkId>.<sealed>`, single-use invitations `MP1.`, replay window), `rewards.js` (goals, reports), `rtc.js` (serverless WebRTC: `iceServers: []`), `family.js` (state, message handling, live-channel registry), `transports.js` (Bluetooth channel from `BtLink.kt`), `ui/family.js` + `ui/incoming.js` (one router for anything that arrives: invitation / envelope / backup / template code). Envelopes are plain text, so NFC tags, the share sheet, Bluetooth, WebRTC and copy-paste are interchangeable carriers.
* **NFC tap.** `NfcApdu.kt` (pure framing, JVM-tested), `NfcOffer.kt` (the one text on offer, 60 s TTL), `NfcOfferService.kt` (HostApduService), `NfcReaderLink.kt` (reader mode, auto-off).
* **Android extras.** `BtLink.kt` (RFCOMM listen/connect, newline-framed), `RunWidget.kt` (RemoteViews + Chronometer, snapshot pushed by the runner), `RoutineWidget.kt` (favourites).
* **People & avatars.** `profiles.js` + `avatar.js` + `levels.js` + `badges.js` are pure; `store.js` keeps `profiles`, mirrors the ACTIVE profile into `settings.personName/age/gender/avatar/mascot` (so most code is unchanged) and exposes `myRuns()` / `runsForProfile()` - always use those, not `state.runs`, for anything personal. Legacy runs without `profileId` belong to the first profile. `ui/avatar.js` draws characters (SVG built from `characterShapes`), the picker and the switcher.
* **Schedule & gear** (`schedule.js`), **QR** (`qr.js` generator, `ui/qr.js` display/scan; native scan = Google code scanner).
* **No server.** Data: IndexedDB (`templates`, `runs`, `kv`). Sharing: self-contained code `M2.<base64url(deflate(json))>` via share sheet / link / NFC.
* **One codebase for UI.** The APK has no UI code of its own; Gradle packages `web/` as assets. Native adds only what browsers cannot: reliable alarms, widget, NFC from the app, vibration.
* **Time.** Run timing is derived from timestamps (`engine.js`), never from tick counts, so throttled/background timers cannot drift; the active run is persisted so it survives reloads.
* **Versioning.** `web/version.json` → PWA, service-worker cache name, APK `versionName/Code`.
* **Trust boundaries.** (1) Imported/shared/restored data → `sanitizeWire`/`normalizeTemplate`. (2) Web → Android → `NativeBridge` argument validation. (3) CSP + escaped DOM building.


## Helpers, journal and its lock (1.10)
- **Pure logic** (unit-tested): `focus.js` (areas → default helpers, per-person overrides win), `calm.js` (breathing phases), `sprints.js`, `mood.js`, `menu.js`, `lock.js`, `journal.js` (storage on top of `db.js`).
- **Per-person settings** live on the profile (`focus`, `tools`, `menu`, `redeemed`); `S.features()` is the single place that answers "is this helper on?". A parent sets them with the `focus` / `menu` link messages; everything received is sanitised (`sanitizeAreas`, `sanitizeTools`, `sanitizeMenu`, `Object.hasOwn`).
- **Journal lock design** (`lock.js`): password → PBKDF2-SHA256 (210k iterations, random salt) → AES-GCM key that wraps an RSA-OAEP private key; the public key stays in the clear so **adding** an entry never needs the password. Each entry/voice note is encrypted with a fresh AES-GCM key wrapped by the public key. The private key is stored a second time, wrapped by a key derived (PBKDF2 + separate salt) from the normalised **security-question answers** - that is the "forgot password" path. Answers are never stored. Failed attempts are throttled (3 free, then 30 s doubling, max 15 min; persisted). The unlocked key lives in memory only and is dropped when the app was hidden for a minute. Forgetting both means the data is gone by design; "Erase journal" is the escape. Limits: a local attacker with the unlocked device can brute-force offline at PBKDF2 speed - short passwords are weak; the journal is never part of backups/sync/links.
- **Voice**: `recorder.js` (MediaRecorder, 180 s cap, tracks always released) and `dictation.js` (Android `SpeechRecognizer` via `DictationLink`, or Web Speech API in browsers). Dictation is opt-in with a privacy notice; a recording is never uploaded by the app. On Android the recognizer and the recorder compete for the microphone, so in the app dictation and recording are separate actions; browsers can do both and show a suggested transcript.
- **Android**: `RECORD_AUDIO` is requested only on first use; `WebChromeClient.onPermissionRequest` grants audio capture to our own origin only (never video); shortcuts open allow-listed routes (`#/calm`, `#/journal`).

## Alarm chains and unplanned interruptions (1.10)
- **Alarms**: `wake.js` (pure) normalises a routine's alarm (first ring + up to 8 more with a gap each; sound/volume/text/voice per ring; `startMode` offer|auto) and flattens it for Android with `nativeRings` - every ring is an independent `setAlarmClock` entry (`<templateId>#<n>`, days shifted when a ring crosses midnight); only the last ring carries the start mode. `AlarmService` plays the chosen system sound (rising = volume ramp) and speaks the text with `TextToSpeech`; the notification/full-screen intent opens the app with `mode`+`text` extras and `ui/offer.js` shows the Start button or starts at once. Browsers use `reminders.js` + `audio.playRing` while the page is open.
- **Unplanned interruptions**: `engine.startInterruption/endInterruption` stop the task clock without counting a pause and push `{key,label,emoji,sec,at,task}` onto `run.unplanned` (sanitised in `sanitizeRun`). `unplanned.js` (pure) detects patterns per routine (>= 4 runs, >= 3 hits and >= 40% of the last 12) and builds the "add as task" change; "look closer" keeps a watch in `kv:watch` and writes an `insight` journal entry. Watches are device-local and not part of backups.

## Template library (1.10)
`library.js` (pure) defines entries (reusable task / routine; sanitised on load and on every backup import, photos only via `isSafePhoto`, caps 100 routines / 300 tasks), the built-in idea catalogue and merge/upsert rules. `store.js` keeps `state.library` in `kv:library`, exposes `saveToLibrary/updateLibraryItem/removeLibraryItem(undo)/createFromEntry`, and includes it in `exportAll`/`importBackup` (merge by id, replace mirrors). `ui/library.js` holds the pickers (big tiles) and the management page. The sample routines are the built-in routine templates (fixed ids).

## Goals, alarms screen, sand clock (1.11)
`cogfun.js` (pure) holds the strategy catalogue and goal logic (sanitise, progress from the linked routine's finished runs since the goal began, weekly check prompt); goals live on the profile (`goals`), a parent's suggestion arrives as the `cogGoal` link message (sanitised) and `sitwith` marks a parent as sitting with the child for 20 minutes. `ui/alarms.js` is the all-routines alarm screen (it reuses `alarmEditor` in a sheet on a copy of the template). The sand clock is an inline SVG updated in `paintLive`. `StatsWidget.kt` shows a bounded snapshot pushed through `native.setStats`.

## Task feelings, thoughts, reports and PDF (1.12)
`difficulty.js` (pure) aggregates the per-task `difficulty` (1-5) and `help` counters stored on each run task (clamped in `sanitizeRun`); `thoughts.js` holds the kind-thought and exercise libraries with age tiers and a no-repeat picker; `ui/taskHelp.js` is the card in the run. `report.js` (pure) builds one model for a run or a period; `ui/report.js` renders it (styles in `css/report.css` - the CSP forbids inline `<style>`), and `pdf.js` makes a real PDF without a library: the element is serialised into an SVG `foreignObject` image (the stylesheet text is embedded in that image), cut at section boundaries into A4 pages, JPEG-encoded and wrapped in a minimal PDF (valid xref, unit/e2e checked). Android: `NativeBridge.sharePdf` -> `MainActivity.sharePdf` writes the PDF (header-checked, size-capped) to the private cache and shares it through a read-only `FileProvider` content URI.

## Smart suggestions, awareness, HTML report, what's new (1.13)
`smart.js` (pure) suggests task times (own history median, else keyword estimate x age x capped help margin) and in-between steps per chosen help; `ui/smart.js` shows them in the editor and never applies anything silently. Steps carry `helper` (`calm|move|thought`) + `helperKey`, normalised in `normalizeTemplate`; `ui/taskHelp.js` turns a helper step into a one-tap exercise in the run. `awareness.js` measures typed estimates (`task.guess`) against reality. `reportHtml.js` builds ONE self-contained interactive file (tabs, count-up, bars/charts drawing, collapsible sections, reduced-motion safe): the report DOM is serialised by `serializeNode` (escapes everything, drops scripts/handlers) - no `innerHTML`/`outerHTML` anywhere. `changelog.js` is the in-app What's new data (a unit test requires the running version at the top); `migrateAlarms()` runs once and switches the alarm on for the ready-made routines only.

## Retrospective (1.14)
`retro.js` (pure) holds the causes, the sanitisers (retros can arrive in backups), `suggestActions` (stuck tasks x causes -> concrete changes, no duplicates, nothing for steps already present), `applyActions` (edits a COPY of the routine: time, helper step, split, alarm shift with midnight wrap, gear, planned interruption, goal request), `impact` (runs before vs after the applied change: on-time share, mean over/under plan, difficulty, stuck-task overrun, interruptions; needs 2 before / 3 after; score -> improved / same / worse) and `overview` (per-type effect, causes, stubborn tasks and the automatic conclusions as `{key, p}` for the UI to word). `store.js` keeps `retros` (one per run) in `kv:retros`, applies changes through `saveTemplate`, restarts the clock (`appliedAt`) on every apply and includes retros in `exportAll`/`importBackup`. `ui/retro.js` is the form, the overview and the Home prompt; `report.js` adds the section.

## Retrospective v2 (1.15)
A look-back record now carries `mode` (guided|free), `scope` (run | the routine's last 5 runs, via `aggregateRuns` - a synthetic typical run so suggestions/candidates are reused), `parts` (feel/tasks/good/change), `status` (draft|done) and `step` (so a guided look-back can be resumed), plus `wentWell` / `later` task lists; a run can have many (`retrosForRun`). `applyActions` also returns per-action undo records (stored on the action, whitelisted by `sanitizeUndo`); `undoActions` replays them in reverse so a later split is undone before an earlier time change looks for its task; `store.undoRetro` removes the goals it created. `focusItems` ranks tasks by stuck count, set-aside count, recent overrun and difficulty; `workedItems` splits changes into helped / not helped plus steady tasks; `dueRun` prefers the run with the most going on. `ui/retro.js` is a small state machine (hub / start screen / form) - guided shows one part at a time and autosaves a draft on every step.

## Voices (1.16)
`speech.js` (pure except the thin speak wrapper) holds the character table (`PRESETS`: gender wanted, human-range pitch/rate baselines, pause factor, variant, optional sound `fx`), `scoreVoice`/`guessGender`/`pickVoice` (quality keywords such as Natural/Neural/Enhanced, penalties for novelty/compact voices, gender match, `variant` for variety), `cleanForSpeech` (emoji and abbreviations), `phrases`/`planSpeech` (phrase chunks with pauses, intonation, deterministic jitter, wording-style openers, animal sounds) and `speakText` (chains utterances with pauses, a watchdog for engines that never fire `end`, cancellable). Settings: `voicePreset` (character id; old ids stay valid), `voiceURI`, `voiceRate` (70-130), `voiceFlavor`. Native alarm speech still uses the system TextToSpeech with the character's pitch/rate. Limits: voices are whatever the device has installed; no voice models are bundled (size, licensing), so real accents/recordings are out of scope.

## 1.18: quiet days, pause and the toolbar
- `holidays.js` (pure): Hebrew date via `Intl` (`u-ca-hebrew`) and Israeli holidays/vacations computed from it; memoised. `wake.js` uses it (`quietDay`) together with the global pause rules (`setAlarmRules`, fed by `store.applyAlarmRules` from `settings.alarmsPause`); `nextRing` / `alarms.nextFire` skip quiet days and paused time (horizon 430 days).
- Android: the web app pushes `setAlarmRules({ pausedUntil, skipDates })`; `AlarmMath.nextFire(..., skip, pausedUntil)` skips those dates (JVM-tested), `AlarmStore` keeps the rules and re-arms; per-ring `offDays` and `tone` (a `content://` ringtone chosen with `pickRingtone`).
- `ui/common.js#toolbar` is the single Home toolbar (one row; dropdown panel in the page flow). `ui/pause.js` = pause sheet + banner. `alarmPause.js` = pure pause values.
- `rejections.js`, `suggestions.js` (weekly check-ins), `difficulty.js#difficultyTrends`, `rewards.js#parentView` (what a parent may see of a child's goals/look-backs).

## Needs, people, skins and voice commands (1.20)
- `needs.js` (pure): a profile's `view` = `{ model, problems }` -> the set of feature ids that stay visible (`visibleSet`); `S.shows(id)` and `S.features()` use it, so the toolbar, search, navigation and run helpers follow. Core features (alarms, library, wizard) are never hidden; "Show everything" resets the view.
- Per-person settings: `profile.prefs` (validated by `PREF_RULES` in `profiles.js`) is mirrored into `state.settings` on profile switch and written back by `updateSettings`, so code that reads `settings.*` is unchanged.
- `skins.js` + `data-skin` / `data-easy` set by `a11y.js` and `theme-boot.js` (no flash); skins are CSS variable sets that keep AA contrast (axe-checked).
- `ui/people.js`: needs sheet, People manager, top-bar profile menu, start-up picker. Settings has a search/jump bar (`settingsBar`).
- Voice commands: `voiceCommands.js` (pure: strict short-phrase matching, longest phrase wins, he + en, dedupe) + `ui/voiceControl.js` (restarting `dictation.js` session, ignores results while `speakingNow()`), wired in `ui/runner.js` (`onVoice`); risky commands only open the usual confirmation and a spoken yes / no answers it.

## Icon styles (1.25)

Colour (1.25.2): each `.vki` gets `data-ic` (0-7, a hash of the icon id) and CSS paints it with `--ic0..--ic7` (light/dark sets); `<html data-iconmono>` (setting `iconMono`, mirrored in `mo.a11y[7]` for the boot script) turns it off.

`data/visual-kit.json` now also holds the 40 `ui` and 55 `features` icons, each in `line` / `duotone` / `filled` (parsed by `parseVisualKit`). `ui/visualKit.js#iconNode(id)` draws one in `currentColor` (the cut-outs `.i-bg` take `--surface`) in the variant `iconVariantFor(settings.iconStyle, settings.skin)` (`SKIN_ICON`: Classic/Ocean/Forest duotone, Sunset/Candy/Bold filled, Slate/Calm line); `refreshIcons()` redraws every `.vki` when the look or the style changes (called from the look subscription in app.js). Used by the Home toolbar (`iconId`), its menu buttons, and the nav tabs; the emoji stays as the fallback until the kit is loaded. The SVG check reads attribute names with digits.

## Visual kit (1.24)
- `data/visual-kit.json` (illustrations `art`, feeling faces `feelings`, per-pack colours `packs`; trimmed from the ChatGPT kit) is parsed by `visualKit.js#parseVisualKit` through `checkIconSvg` (the avatar allow-list plus pathLength / fill-rule / clip-rule; invalid items are dropped). `ui/visualKit.js` draws them (`artNode`, `feelingNode`, `emptyState`) with createElementNS; the pictures use the classes `k1..k8` that css/app.css maps to `--k1..--k8`, set per look (`SKIN_PACK`: default=sunrise, ocean, forest, sunset, candy, slate, calm=calm-mono, bold=bold-focus) in light and dark - a unit test checks that the CSS colours equal the pack colours.
- Not adopted yet (kit round 4): task icons (the app stores emoji), feature icons, awards, animations, the style-pack switch, adaptive-icon layers.

## Avatar kit and My avatars (1.23)
- `data/avatar-pack.json` (original art generated from `docs/AVATAR_PACK_PROMPT.md`, 283 parts, 141 KB) is parsed by `avatarKit.js#parsePack` with a strict regex allow-list (`checkSvg`: known elements/attributes only, local `url(#id)` only, no text/style/script/links); invalid options are dropped. A kit avatar is `{ k:'kit', p:{slot:id}, c:{colour:#hex} }` (`sanitizeKit`), a share code is `SRAV1.` + base64url of the ids and colours (`encodeKit`/`decodeKit`).
- `ui/avatarKit.js` loads the pack once (cached by the service worker) and draws the layers in the designer's order with createElementNS (never markup strings); colours are CSS variables `--c-skin` ... on the node; animations swap variants (two-frame groups `fa`/`fb` toggled by CSS keyframes, a blink) and move the figure with the existing `av-*` keyframes; `node._kitSet(state)` / `_kitUpdate(kit)`. `ui/avatarStudio.js` (editor), `ui/avatarLibrary.js` (My avatars), `ui/avatarShare.js` (share / import by code). The library lives in `kv.avatarLib` (store: `saveAvatarDesign`, `duplicateAvatarDesign`, `deleteAvatarDesign` with undo) and in the backup file.
- Messages inside sheets are written into the sheet (a toast would sit behind the top-layer dialog).

## NLP and calm animations (1.22)
- `nlpTools.js` (pure): the six tools as step lists (`text` / `pause` / `words`), `flagWords` (whole-word detection of absolute / must / can't words, he + en) and `composeNote`; `ui/nlp.js`: the wizard sheet (opens from the NLP page, a special task's run-screen button) and the page. NLP is a `needs.js` model (`nlp` feature id) and a special-task group; the notes go to the journal as ordinary `note` entries (no schema change). The app states that evidence for NLP is limited; no result claims anywhere.
- `reduceMotion` pref -> `data-motion="calm"` on `<html>` (set by `a11y.js`, mirrored for `theme-boot.js`); one CSS rule disables animation/transition, `fx.reducedMotion()` and the calm corner honour it.

## Kids / full view switch (1.21.1)

## Sharing, special tasks, points and moving routines (1.21)
- `template.owners` ([] = everyone) and `S.myTemplates()` / `S.canSee()`: the UI lists only the active person's routines; alarms and the widget still use every routine on the device. Deleting a person removes their id from `owners` (a routine nobody sees becomes shared, never lost).
- `specialTasks.js` (pure catalogue, grouped, searchable) + `task.helper` (whitelisted by `isHelper`): the run screen's task-help card opens the tool; calm-corner tools run without pausing the clock.
- `points.js` (pure): `scoreTask` / `scoreRun` (stored on the run as `run.score`, sanitised on read), `podium`, `series`, `totalPoints`; `ui/podium.js` + `fx.fireworks`; `pointsCard` in Statistics. Off by default; the calm pace never takes points away.
- `routineIO.js` (pure) + `ui/routineIO.js`: a versioned routines file (`sonrise-routines`) and also full backups are read strictly (size/count limits, rebuilt through `normalizeTemplate`, new ids, alarm off).

## Calm kit scenes (1.26)
`web/data/calm-kit.json` (built by `scripts/build-calm-kit.mjs` from the extracted ChatGPT zips, later dirs win) -> `parseCalmKit` (strict allow-list, drops bad scenes) -> `ui/calmScene.js` (`sceneStage().show(idA, idB, t)` cross-fades two layers; copies elements with createElementNS). `ui/calm.js` picks the scene per tick: `breath-<pattern>-0..4` via `frameMix(size)`, `imagery-<guide>-f1..f4` via `storyFrame`, `grounding-<n>`, `bodyscan-<zone>` via `scanZone`. `calmVisual` setting: scene | avatar | circle. The avatar mode sets `--p` on the kit avatar (`.avatar-breathe .kit-move` scales).
